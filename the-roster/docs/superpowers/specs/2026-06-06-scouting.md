# Scouting & Artist Import

**Date:** 2026-06-06  
**Status:** Approved

## Goal

Let players evaluate artists before signing through a timed scouting mechanic, and add artists missing from the database via a Spotify search flow that auto-starts a scout with a one-week bonus.

## Events

One new event type added to `label_events`:

| Type | Trigger | Payload |
|------|---------|---------|
| `scout_completed` | Weekly tick Pass 4 (per completed scout) | `{ weeks_taken: number }` |

Activity feed description: "Scout complete — [artist]"

## Data Model

```sql
-- Migration 007
CREATE TABLE scouts (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  label_id     uuid NOT NULL REFERENCES labels(id) ON DELETE CASCADE,
  artist_id    uuid NOT NULL REFERENCES artists(id) ON DELETE CASCADE,
  started_at   date NOT NULL DEFAULT CURRENT_DATE,
  completes_at date NOT NULL,
  completed_at date,
  is_discovery boolean NOT NULL DEFAULT false,
  UNIQUE (label_id, artist_id)
);

CREATE INDEX ON scouts (label_id, completed_at);

ALTER TABLE scouts ENABLE ROW LEVEL SECURITY;

CREATE POLICY "scouts: own label" ON scouts
  FOR ALL USING (auth.uid() = label_id) WITH CHECK (auth.uid() = label_id);
```

RLS: `own label` — `FOR ALL USING (auth.uid() = label_id)`.

`UNIQUE (label_id, artist_id)` enforces one scout per label per artist at a time.

Also add `'scout_completed'` to the `label_events.event_type` CHECK constraint:

```sql
ALTER TABLE label_events DROP CONSTRAINT label_events_event_type_check;
ALTER TABLE label_events ADD CONSTRAINT label_events_event_type_check
  CHECK (event_type IN ('royalty_paid','artist_signed','contract_expired','tier_up','scout_completed'));
```

## Scout Duration

```
base = { underground: 8, emerging: 6, rising: 4, established: 3 }[tier]
affinity_reduction = hasAffinity ? ceil(base × 0.2) : 0   -- cap: 20% of base
discovery_reduction = isDiscovery ? 1 : 0
duration_weeks = max(1, base - affinity_reduction - discovery_reduction)
completes_at = started_at + duration_weeks × 7 days
```

**Affinity check:** the label has at least one active contract where the contracted artist shares `country` OR `genre` with the artist being scouted. Cap is one reduction of 20% regardless of how many affinities exist.

**Discovery bonus** (`is_discovery = true`): applied when the artist was not in the database before the player requested them. Reduces duration by 1 additional week.

## Scout Report (live)

Computed at read time from the artist's latest `artist_stats_daily` row. Three outputs:

### Pattern Classification
Computed from `daily_streams_top10` over the last 14 available rows:
- Coefficient of variation = std_dev / mean (clamped to rows with non-null streams)
- CV < 0.30 → `organic`
- CV > 0.80 AND max > 3 × mean → `spike`
- Otherwise → `mixed`
- Fallback when fewer than 3 rows available: `mixed`

### Signing Bonus Estimate
Tier bonus ranges from CLAUDE.md. Monthly listeners position within the tier range:
```
tier_ranges = {
  underground: { min: 0, max: 50_000, bonus_min: 500, bonus_max: 2_000 },
  emerging:    { min: 50_000, max: 500_000, bonus_min: 5_000, bonus_max: 20_000 },
  rising:      { min: 500_000, max: 2_000_000, bonus_min: 20_000, bonus_max: 80_000 },
  established: { min: 2_000_000, max: 10_000_000, bonus_min: 80_000, bonus_max: 300_000 },
}
position = clamp((monthly_listeners - tier_min) / (tier_max - tier_min), 0, 1)
estimate = round(bonus_min + position × (bonus_max - bonus_min))
```
Displayed as "~$X" (point estimate).

### Momentum Confidence
Based on `listener_growth_28d` (null → `stable`):
- `|growth| < 5%` → `stable`
- `|growth| 5–15%` → `moderate`
- `|growth| > 15%` → `volatile`

## API Routes

### `POST /api/scouts`
Start a scout on an artist already in the database.

Request body: `{ artist_id: string }`

Checks (in order):
1. Auth
2. Active scout count for label < 8 (scouts where `completed_at IS NULL`)
3. No existing scout for this label+artist (unique constraint)
4. Artist exists and tier is not `major`

Computes affinity (active contracts sharing country or genre), duration, `completes_at`.

Inserts scout row. Returns scout.

### `GET /api/scouts`
Returns all scouts for the authenticated label (active + completed), joined with `artist_id`, `artist_name` (from artists table), `completes_at`, `completed_at`, `is_discovery`.

### `POST /api/scouts/discover`
Search Spotify for a missing artist.

Request body: `{ query: string }`

- Calls Spotify Web API: `GET https://api.spotify.com/v1/search?q={query}&type=artist&limit=3`
- Uses client credentials flow (`SPOTIFY_CLIENT_ID` + `SPOTIFY_CLIENT_SECRET` env vars)
- Returns top 3 Spotify matches: `{ spotify_id, name, followers }`

Does NOT create any database rows yet.

### `POST /api/scouts/discover/confirm`
Create the artist + start the scout.

Request body: `{ spotify_id: string }`

1. Check if `artists` row already exists for this `spotify_id`
   - If yes: start a regular scout (no discovery bonus — artist was already in DB)
   - If no: create `artists` row, then start scout with `is_discovery: true`
2. Artist creation: fetch artist profile from Spotify (`GET /v1/artists/{id}`) for name, genres, popularity. Tier estimated from popularity: 0–29 → underground, 30–54 → emerging, 55–74 → rising, 75+ → established. `country` left null (pipeline will populate).
3. Scout creation follows the same rules as `POST /api/scouts` (8-slot limit, etc.)
4. Returns scout + artist.

The pipeline scraper will overwrite the estimated tier/stats on its next daily run.

## Weekly Tick Pass 4

After Pass 3 (tier-up detection), before `return Response.json(...)`:

```typescript
// ── Pass 4: complete overdue scouts ─────────────────────────────────────────
const { data: overdueScouts } = await supabase
  .from('scouts')
  .select('id, label_id, artist_id, started_at, completes_at')
  .lte('completes_at', statsDate)
  .is('completed_at', null)

for (const s of overdueScouts ?? []) {
  const { error } = await supabase
    .from('scouts').update({ completed_at: statsDate }).eq('id', s.id)
  if (error) continue

  const artistName = artistMap.get(s.artist_id)?.name ?? 'Unknown'
  const weeksStarted = Math.round(
    (new Date(s.completes_at + 'T00:00:00Z').getTime() -
     new Date(s.started_at + 'T00:00:00Z').getTime()) / (7 * 86400_000)
  )

  await supabase.from('label_events').insert({
    label_id: s.label_id,
    event_type: 'scout_completed',
    artist_name: artistName,
    payload: { weeks_taken: weeksStarted },
  })
}
```

Note: `artistMap` is already built in Pass 2 for active contracts only. Pass 4 needs artists for scouts that may not have active contracts — fetch them separately in a second batch query before the Pass 4 loop:

```typescript
const scoutArtistIds = (overdueScouts ?? [])
  .map(s => s.artist_id)
  .filter(id => !artistMap.has(id))

if (scoutArtistIds.length) {
  const { data: scoutArtists } = await supabase
    .from('artists').select('id, name').in('id', scoutArtistIds)
  for (const a of scoutArtists ?? []) artistMap.set(a.id, a)
}
```

## Out of Scope

- Scout cancellation
- Multiple scouts for the same artist (unique constraint prevents this)
- Reputation gating on scout data (separate progression feature)
- Scout notifications / push alerts
- Competitor scout counts (Veteran reputation feature)
- Pipeline auto-triggered on import (pipeline runs on its own schedule)
